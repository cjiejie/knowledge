# Local Planner (局部规划器/控制器)

在 Nav2 中，局部规划器运行在 **Controller Server** 节点中。它的主要职责是接收由全局规划器（Global Planner）生成的全局路径，并结合 **Local Costmap（局部代价地图）** 和机器人当前的里程计信息，计算出实时的速度指令（`cmd_vel`）下发给底盘。

由于局部规划器直接影响机器人的动态表现（如避障、平顺性、是否卡死），它通常是导航系统中调参最复杂、最关键的部分。

## 核心职责

1. **路径跟踪 (Path Tracking)**：努力让机器人贴合全局规划出来的路径。
2. **局部避障 (Local Obstacle Avoidance)**：如果突然出现动态障碍物（如行人），需在局部范围内绕开它，或在无法绕过时紧急制动。
3. **运动学限制 (Kinematics Constraints)**：确保输出的速度指令不超过机器人的最大速度、最大加速度等物理限制。
4. **精确对准 (Goal Alignment)**：在到达目标点附近时，精准调整位置和朝向。

## 常见的局部规划器插件

Nav2 提供了多种强大的控制器插件，以适应不同类型的机器人底盘（差速、全向、阿克曼等）。

### 1. DWB Controller
- **算法基础**：动态窗口法 (Dynamic Window Approach, DWA) 的重构与扩展版。
- **原理**：
  1. 在机器人的速度空间 $(v_x, v_y, \omega)$ 中，根据当前速度和最大加速度，计算出一个下一周期内能达到的“速度窗口”。
  2. 在窗口内采样多组速度指令，模拟这些指令下机器人的运行轨迹。
  3. 使用多个“评价函数 (Critics)”对这些轨迹打分（例如：偏离全局路径扣分、离障碍物太近扣分、没有对准目标扣分）。
  4. 选出得分最高的轨迹，输出对应的速度。
- **特点**：高度模块化，所有的评分项都可以作为插件增删和调节权重。
- **适用场景**：差速和全向机器人。

### 2. MPPI Controller (模型预测路径积分)
- **算法基础**：Model Predictive Path Integral (MPPI)。
- **原理**：基于优化的控制方法。利用 GPU/CPU 强大的并行计算能力，在预测时域内生成成千上万条随机控制轨迹，通过代价函数评估后，加权平均得出最优控制输出。
- **特点**：
  - 能处理极其复杂的代价函数和非线性运动学模型。
  - 对于狭窄通道、动态障碍物的响应比 DWB 更加平滑且智能。
- **适用场景**：算力充足的平台，要求高动态避障能力的差速、阿克曼及全向机器人。

### 3. TEB Local Planner
- **算法基础**：Timed Elastic Band (时间弹性带)。
- **原理**：将路径规划转化为一个多目标的优化问题。它不仅考虑了几何路径，还把时间 $t$ 作为优化变量，同时考虑了运动学约束（特别是前轮转向的非完整约束）。
- **特点**：
  - 原生支持阿克曼转向底盘（如自动驾驶汽车），支持倒车。
  - 生成的轨迹在时间和空间上都是最优的。
  - （注：TEB 是社区维护的第三方插件，并非 Nav2 官方默认核心插件，但使用极为广泛。）
- **适用场景**：阿克曼底盘、需要精细倒车或考虑最小转弯半径的车辆。

### 4. RPP Controller (Regulated Pure Pursuit)
- **算法基础**：调节纯追踪算法。
- **原理**：经典的纯追踪算法会在全局路径上寻找一个“前瞻点 (Lookahead Point)”，然后控制机器人朝着这个点开去。RPP 在此基础上增加了速度调节（例如在转弯时减速、遇到障碍物时减速）。
- **特点**：
  - 计算极快，资源消耗极低。
  - 路径跟随极为精确，但**不具备主动局部避障能力**（遇到障碍物只会停下，而不是绕开）。
- **适用场景**：工厂里的 AGV（磁条/轨道式循迹的替代方案）、只需要严格走固定路线的清扫机器人。

## 碰撞检测 (Collision Checker)

在 Nav2 的 Controller Server 中，碰撞检测被独立出来。局部规划器在采样轨迹后，会调用 Collision Checker 来验证该轨迹上的机器人轮廓（Footprint）是否会与局部代价地图中的障碍物发生重叠。

如果最优轨迹会导致碰撞，控制器会拒绝输出该速度，并可能向上层（BT）返回失败，从而触发恢复行为。
