# ESDF (欧几里得符号距离场) 原理与接入指南

在机器人的三维感知与轨迹规划中，环境地图的表达方式直接决定了规划算法的上限。传统的 2D 占据栅格地图 (Occupancy Grid Map) 或 3D 八叉树地图 (OctoMap) 只能告诉我们“这个位置有没有障碍物”，而 **ESDF (Euclidean Signed Distance Field，欧几里得符号距离场)** 则能告诉我们“这个位置距离最近的障碍物有多远，以及应该朝哪个方向远离它”。

ESDF 是当今无人机 (UAV) 快速穿梭飞行、机械臂避障以及高动态移动机器人轨迹优化的**核心感知基础设施**。

---

## 1. 为什么需要 ESDF？

### 传统占据栅格 / OctoMap 的局限性
在占据栅格地图中，空间被划分为 0（空闲）和 1（占据）。如果机器人在空闲区域内进行基于梯度的轨迹优化（如基于样条曲线的轨迹平滑），算法无法获得梯度信息（因为周围全是 0，没有坡度），机器人不知道往哪边走才能离障碍物更远，最终生成的轨迹很容易紧贴着障碍物擦过，非常危险。

### ESDF 的降维打击：自带梯度
ESDF 是一种连续的空间表达方式。在 ESDF 地图中，空间中的每一个体素 (Voxel) 都存储着一个浮点数：**距离最近障碍物的欧氏距离**。
- **正值 ( > 0 )**：在障碍物外部，数值越大表示越空旷。
- **零 ( = 0 )**：正好在障碍物表面。
- **负值 ( < 0 )**：在障碍物内部（穿透了障碍物）。

**最大优势**：因为空间中每个点都有一个连续的距离值，规划器可以直接对空间求导，得到距离场梯度 ($\nabla d$)。轨迹优化算法（如 Minimum Snap 或 B-Spline 优化）可以利用这个梯度，像“水往低处流”一样，自动将轨迹推离障碍物，生成平滑且极其安全的飞行/行驶轨迹。

## 2. ESDF 的构建原理与难点

直接从原始点云计算 ESDF 的时间复杂度极高，因为理论上需要计算空间中每一个空闲体素到所有障碍物点云的最短距离。主流的框架（如 Voxblox, FIESTA）采用了分步或增量的策略。

### 经典构建流程 (以 Voxblox 为例)

1. **传感器输入融合 (Raycasting)**
   - 接收深度图或 3D 激光点云，结合相机的位姿 (Odometry / TF)，通过光线投射 (Raycasting) 将传感器到障碍物之间的空间标记为 `Free`，障碍物表面标记为 `Occupied`。
2. **构建 TSDF (截断符号距离场)**
   - TSDF (Truncated Signed Distance Field) 只在障碍物表面附近的一个小范围（截断距离内）计算精确的符号距离。对于远处的空间，直接赋予一个固定的最大截断值。这一步非常快，主要用于滤除传感器噪声，生成高质量的 3D 表面模型。
3. **从 TSDF 推演 ESDF (距离传播)**
   - 这是最耗时的一步。算法以 TSDF 中值为 0 的障碍物表面为“种子点”，像水波纹一样向外围的空闲空间进行“波前传播” (Wavefront Propagation)，不断更新相邻体素的最短距离值，直到填满整个 ESDF 地图。

### 增量式更新 (FIESTA 的突破)
早期的框架每次环境变化都要全局重算 ESDF，极其卡顿。近年来如 **FIESTA** 等算法引入了双向 BFS（广度优先搜索）和增量更新机制。当某个障碍物出现或消失时，只在局部区域内更新受影响的距离值，实现了极高的实时性（能在普通 CPU 上跑出几十 Hz 的更新率）。

## 3. ROS / ROS2 接入指南

要将 ESDF 接入你的机器人系统，通常不需要从头手写，而是集成开源框架。最常用的是 ETH ASL 实验室的 **Voxblox** 或浙大 FAST 实验室的 **FIESTA**。

### 核心输入 (Inputs)
为了让 ESDF 框架正常工作，你需要提供以下两个核心数据流，且它们的时间戳必须严格对齐：

1. **传感器数据**
   - 可以是 PointCloud2 (激光雷达或深度相机生成)。
   - 可以是 Depth Image (深度图，处理速度更快，因为保留了 2D 投影结构)。
2. **高精度里程计 / TF**
   - 需要传感器当前在世界坐标系 (`odom` 或 `map`) 下的位姿。如果位姿漂移严重，建出来的 ESDF 会出现重影，直接导致机器人规划撞墙。

### 核心输出 (Outputs)
接入后，系统可以通过两种方式利用 ESDF：

1. **直接代码级查询 (C++ API)**
   - 规划节点直接 `#include` ESDF 地图对象的头文件，在代码中调用类似 `getDistanceAndGradient(x, y, z, &distance, &gradient)` 的接口，这是轨迹优化最常用的方式。
2. **发布 2D 切片 (ESDF Slices)**
   - 将 3D ESDF 地图在特定高度 (如 Z=0.5m) 处切一刀，投影成 2D 栅格地图发布出来供传统的 Navigation / Nav2 Costmap 使用。

## 4. 实践中的踩坑与细节调优

在实际机器人的集成中，ESDF 非常“娇贵”，常常需要调优：

### 1. 动态障碍物的“拖尾”问题
如果有人从机器人面前走过，ESDF 中往往会留下一条由空到满再到空的残影。这是因为雷达扫描需要时间，Raycasting 清除旧障碍物也有延迟。
- **对策**：调节 `clear_sphere` 半径参数，强制清除机器人周围的残留点；或者在前端加入独立的运动物体剔除模块（如基于深度学习的语义分割过滤）。

### 2. 体素分辨率 (Voxel Size) 的权衡
- `voxel_size` 设为 `0.05`（5cm）：精度高，细节丰富，但内存爆炸，更新极慢。
- `voxel_size` 设为 `0.2`（20cm）：速度飞快，但机械臂可能会撞到细小的桌腿。
- **对策**：室内无人机或机械臂通常设为 `0.05m ~ 0.1m`，室外无人车可以放宽到 `0.2m`。

### 3. 未知区域 (Unknown Space) 的处理
ESDF 必须明确区分“已知空闲 (Free)”和“未知 (Unknown)”。在轨迹规划时，如果把未知区域当作空闲区域，机器人可能会全速冲进未被雷达扫到的死角发生碰撞。
- **对策**：在查询 ESDF 时，务必检查返回的属性。如果目标点在 Unknown 区域，通常需要规划器增加惩罚代价，或者先执行探索性移动。
